Docs

ktp-kit reads the KTP on the user's device and hands you the result as JSON. Forms, validation and storage stay in your app. These docs go from install to the data reaching your server.

Install

  1. Install the package: 
    npm install ktp-kit
  2. Copy the models and runtime (4.9 MB, pre-compressed) to your app's public folder: 
    npx ktp-kit assets public/ktp-kit
    Run it again after every ktp-kit update. This folder's path is your base.
  3. Send these two headers on pages that use ktp-kit, so WebAssembly can use several threads. Reads get about 3x faster, 2-4 seconds per KTP on a mid-range phone: 
    Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
    The side effect: scripts, images and iframes from other domains must allow cross-origin use. Without these headers ktp-kit still works, just slower.

Usage

Pick one. The result is the same.

HTML (Laravel Blade, PHP, Django, Rails, Svelte...)

<script type="module">import "ktp-kit/element";</script>
<ktp-capture base="/ktp-kit/" lang="en"></ktp-capture>
<script>
  document.querySelector("ktp-capture").addEventListener("ktp-result", e => {
    console.log(e.detail);   // see Result below
  });
</script>

Attributes: base (the path from step 2), lang (id or en), upload="false" to hide the upload button. Events: ktp-result, ktp-state, ktp-error. Style it with CSS variables and ::part(), see the README.

React

npm install @ktp-kit/react

import { KtpCapture } from "@ktp-kit/react";
<KtpCapture base="/ktp-kit/" onResult={r => setKtp(r)} />

Vue

npm install @ktp-kit/vue

<KtpCapture base="/ktp-kit/" @result="r => ktp = r" />

Headless (your own UI)

import { useKtpCapture } from "@ktp-kit/react";   // same in @ktp-kit/vue
const { videoRef, state, shoot, retake, readFile } = useKtpCapture({ base: "/ktp-kit/" });
// state.status: searching | adjust | hold | reading | done | error
// state.hint: a message key (MESSAGES), state.corners: card corners to draw
// state.result: the result when status is "done" (card as pixels, not a Blob)

Node.js and CLI

npx ktp-kit read foto/*.jpg          # one JSON line per photo
npx ktp-kit read foto/*.jpg --csv    # or CSV

perlu_dicek

Fields the user should check again, each with a reason code. You decide the text your users see.

CodeMeaning
nik_mismatchThe card disagrees with what the NIK encodes (birth date, gender). One of them was misread.
from_nikThe text on the card was unreadable, so the value comes from the NIK. Usually right, but not read from the card.
low_confidenceName or address: the model was unsure of at least one letter, usually from blur or glare. On test photos this flag caught about 3 in 4 misread names.

Example form

Add inputs only for the fields you need. As long as each input's name matches a result field, this snippet fills them. Other fields are ignored.

<ktp-capture base="/ktp-kit/"></ktp-capture>
<form id="signup">
  <input name="nik"> <input name="nama"> <input name="tanggal_lahir">
  <button>Sign up</button>
</form>
<script>
  let ktp = null;
  const form = document.getElementById("signup");
  document.querySelector("ktp-capture").addEventListener("ktp-result", e => {
    ktp = e.detail;
    for (const [k, v] of Object.entries(ktp)) if (form.elements[k]) form.elements[k].value = v ?? "";
  });
</script>

If users must not change a field, add readonly. To mark the fields to check:

for (const [field, reasons] of Object.entries(ktp.perlu_dicek))
  form.elements[field]?.classList.add("check-me");

React

const [form, setForm] = useState({ nik: "", nama: "" });
<KtpCapture base="/ktp-kit/" onResult={r => setForm({ nik: r.nik ?? "", nama: r.nama ?? "" })} />
<input value={form.nik} onChange={e => setForm({ ...form, nik: e.target.value })} />

Send to a server

Submit the form as usual. Send the KTP photo only if you really need to store it.

form.addEventListener("submit", async e => {
  e.preventDefault();
  const data = new FormData(form);
  data.append("ktp", ktp.card, "ktp.jpg");   // optional
  await fetch("/signup", { method: "POST", body: data });
});

On the server, treat this as ordinary user input, because users can edit the form. Check the NIK again with the same functions:

import { nikValid, nikConflicts } from "ktp-kit";

app.post("/signup", upload.single("ktp"), (req, res) => {
  const { nik, tanggal_lahir, jenis_kelamin } = req.body;
  if (!nikValid(nik)) return res.status(400).json({ error: "Invalid NIK" });
  const diff = nikConflicts({ nik, tanggal_lahir, jenis_kelamin });   // e.g. ["tanggal_lahir"]
  if (diff.length) return res.status(400).json({ error: "Does not match the NIK", field: diff });
  // save to the database
});

Need to know the NIK is really registered? That takes a Dukcapil check through an authorised provider. Call it from your server, and only for sign-ups that need it.

Offline

On first use, ktp-kit stores the models on the device (Cache API). After that, reading works with no internet while the page is open. For the page itself to reload offline, your app needs a service worker that caches its own HTML, JS and CSS. A short example is in apps/demo/sw.js.

Privacy

The KTP photo and data stay on the device until your own app sends them. ktp-kit's only network requests download its models. Indonesia's data protection law (UU PDP) asks you to collect only what you need, so send only the fields you use, and skip storing the KTP photo unless it is required.
